# Make autosaved Note creation idempotent

Each Note Draft sends a stable client-generated UUID in `Idempotency-Key`, unique per owner, so retrying an identical ambiguous initial autosave returns the current Note without creating or mutating it; a changed payload is rejected. Equality uses a runtime-keyed HMAC fingerprint rather than retaining a second private snapshot. Hard deletion keeps a content-free key/identity/keyed-fingerprint tombstone, with no document, title, attachment, or response snapshot, so identical and changed delayed replays remain distinguishable without recreating deleted writing. Initial Reflection creation also requires a stable client-generated UUID in `Idempotency-Key` and uses the same keyed-fingerprint replay rule; later updates omit the header. Subsequent saves are serialized per document and coalesce newer edits, while a separate bounded rich-text save budget starts at 60 requests per authenticated user per minute so autosave cannot exhaust timer and history mutation capacity.
